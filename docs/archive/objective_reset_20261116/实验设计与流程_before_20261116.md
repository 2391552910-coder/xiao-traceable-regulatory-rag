# 实验设计与流程

任务版本：2026-10-13。总目标是完成支撑大论文的小论文算法与实验，以中科院二区计算机类期刊为投稿目标。任务边界见[项目任务与验收](项目任务与验收.md)。

> **状态：以下标注与人工核验流程为旧版研究方案，2026-10-29起不再执行。项目不新增人工标注或双人盲审。**历史标签可按其原有来源复算；现有证据不足时相应指标保持未测或收窄主张。本文其他与“新增人工标签”冲突的流程、指标和准入门槛均只作历史记录。

以下区分已有原型与正式研究设计；计划中的新配置、指标和数据结构尚未全部实现。不能将本文件直接作为已完成实验的论文结果部分。

## 1. 研究问题与方法假设

- **RQ1**：在相同语料与标注下，条款切分、维度路由、Qwen3 检索/重排是否改善监管证据的召回与排序？分析各组件以及成本。
- **RQ2**：年报和法规双库分别检索后用于生成，是否比单库检索或不带引用的生成更能提供有原文支持、来源可定位的评价内容？
- **RQ3**：切分、查询扩展、双库召回、融合、重排和适用时间过滤各自贡献多大？
- **RQ4**：在年报证据缺失、法规不适用或版本错误、证据冲突及不可回答场景下，系统能否避免无依据断言并正确说明证据不足？

研究假设由人工核验的双源证据样例检验，不要求预先将全部年报整理成事实表。评价论断逐项检查年报证据是否支持公司相关陈述、法规证据是否相关且在目标时点适用、引用是否能回到冻结来源。

以上是待检验假设，不预设效果方向、引用正确率或 p 值。相关工作与差异审查见[研究依据与微调决策](研究依据与微调决策.md)。

## 2. 数据与划分

### 2.1 监管语料

清单内 315 篇对应 7,840 块，其中有条款号 7,525 块；当前 loader 扫描全部 txt，实际为 319 篇、7,899 块。DOC001–DOC003 是早期节选，DOC004 已替换为内控规范全文并被 Q22 gold 使用，不能将四个文件一律删除。

正式冻结前：登记 DOC004、隔离节选、审计重复与正文完整性；建立来源、版本、发布日期、生效/失效日期、正文哈希和字符区间。保留历史版本用于事件时点判断，不能把“最长文本”或“当前有效”等同于“在 2024 年适用”。

法规、处罚决定与案件通报分别记录证据角色。案例不能直接充当普遍法规；处罚正文中出现“第 X 条”可能只是援引其他法律，不自动等同于该文书的结构边界。条款号解析率也不等同于完整条款切分正确率。

### 2.2 检索标注

当前 40 条弱标签为 `weak_auto`；40 条 AI 双通道仲裁候选为 `ai_dual_pass_adjudicated`，共 226 个相关块。平均逐查询 Kappa 约 0.760 属于 AI 通道一致性，不能写成双人人工一致性或全局 Kappa。

至少 200 题、四维度各 50 题和 40/160 划分是历史规划目标，尚未证明可行，也不是冻结配额。2026-10-15 暴露审计发现至少 15 家公司有显式问题或先导暴露，39 家均有候选线索文件；严格“材料未进入工作区”的未接触公司数为 0。文件存在不表示逐行阅读或用于调参。原 8/31 公司隔离方案已被本次审计取代。当前正式双源问题及冻结最终测试标签均为 0，候选池未证明能支持 160 个最终问题。D1–D4 仍是研究范围；其中需要第三方声誉等外部事实、而双源输入没有相应原始材料的问题，应列为输入不足挑战；若某 D4 问题确有年报和适用法规双源证据，仍可按同一标准纳入主集。应先清点可支持的独立问题族，再预登记实际题量、分层配额和划分。按语义问题族、事件及重叠证据区间建立连通组，隔离开发与最终测试的问题、标签及调参输出；同一公司可以出现在两侧，39 家年报是共同检索语料。测试内容经独立复核并冻结后，结论仅适用于共享语料上的留出问题，不能声称未见公司泛化。需要公司级泛化结论时，须另收并审计未暴露公司的数据。候选池使用多检索器结果、人工补搜和随机负例；双人独立复核及仲裁仍是计划，只有留下真实记录后才能报告完成。协议见[标注规范](标注规范.md)。

条款与滑窗比较必须映射到统一的原文字符区间/证据单元。不能以 `C` 和 `W` 块 ID 相等计算命中；碎片只有满足标注的必要证据覆盖条件才算命中。

问题分组的实现入口为 `scripts/audit_evaluation_groups.py`；六表结构检查使用 `scripts/validate_dual_source_annotations.py --split-policy question_evidence_groups`。旧校验器默认仍为历史公司隔离规则，不能不带参数就声称检查了本节的新协议。新实现保留实际分割标签，对显式问题族、事件ID及重叠目标证据求连通分量，并对跨开发/测试的连通组报错；同一公司或日期本身不自动连接。任何缺失语义映射、跨格式法规身份或不兼容坐标都需另行复核，分组数量不是独立样本量认证。

### 2.3 年报、法规双库与生成评测

年报 PDF 与法规文件都是系统直接输入的文档。导入时分别登记来源、主体/文档身份、报告年度或法规版本及已知日期；解析文本，扫描页按需 OCR；切分时保留 PDF 物理页、文本字符区间和原文哈希等来源坐标，再分别建立年报库和法规库索引。用户问题触发两路检索：年报库提供公司证据，法规库提供相关且适用的条款；生成内容将论断与两类来源分别关联，并在任一证据链不足时显式说明。

39 家 2024 年报是先导文档集合，不等于 39 个独立评测样本，也不支持对全部 A 股作总体推断。现有材料已为全部 39 家保存候选线索文件，但这不等于候选行都经人工审阅；严格未接触材料公司的测试组当前不可构造。主评测拟按问题族、事件及重叠证据区间做开发/测试隔离，法规语料作为共同检索输入；同一事件或可互相复述的证据不得跨组。测试问题、标签和输出须与开发、调参隔离，完成独立复核及冻结后才能称为最终测试评测。结果只能支持共享语料条件下对保留问题的结论，不得写成公司级泛化。若后续仍按公司分组，必须先扩大并重新审计公司样本框，再按同公司多年度整体分组。法规语料须保留版本、发布日期、生效/失效日期和适用时间信息；事件日期未知时不能强行判定法规适用。

评测标注单位是问题及其双源证据：评价问题、需要回答的论断要点、支持这些要点的年报页/段、相关法规版本/条款、各引用支持关系，以及可回答性/证据不足标签。人工复核用于评估检索与生成是否找对、用对和引对来源；不要求穷尽抽取所有公司事实。自动候选可辅助发现评测段落，但不得直接作为 gold。年报未提及不能标成事件不存在；年报自述支持的是“年报披露了该事项”，若要断言外部事件确实发生，需在系统输入中有相应外部原始证据。

### 2.4 合成与微调数据

已有 600 条模板查询和 3,600 个 Rerank 对，仅用于联调和探索。query_id 不跨 split，但正例条款及法规跨组，不能据此宣称无泄漏。

如开展微调，先按法规族/同源条款划分，再合成问题、挖难负例和去重；最终测试查询及标签保持隔离。知识库作为共同检索语料不等于允许使用测试监督。另设跨法规泛化测试，具体方案见[微调决策](研究依据与微调决策.md)。

### 2.5 自建主集与公开外部验证

主实验采用自建双源评价集，以年报 PDF、历史适用法规文件和问题级人工证据标签检验双库检索及引用生成。公开基准只补充验证其标签实际支持的检索或证据归因能力，不能以一般金融 QA 结果替代中国公司自律评价验证。

外部候选为 [LOFin / Open-domain Financial QA](https://huggingface.co/datasets/HYdsl/Open-domain_Financial_QA)，来源为 [HiREC 论文](https://aclanthology.org/2025.findings-acl.855/)及[官方代码/数据入口](https://github.com/JaeyoungChoe/LOFin-bench-HiREC)。本机已取得数据集固定 revision `93df3a9f93ded87b46cb5155f9026e8e76d8a2b6` 的全部8个仓库原文件并校验Git blob/SHA256；5个JSONL合计3031行，按题号去重为1595题，按答案类型的925/273/397题互不重叠。60行CSV是预览，不能再增加题量；同题号跨文件5处题干及15处答案值差异保留待处理，不能直接判为错标或自行覆盖。原始文件、定位和审计见 `results/runs/external_lofin_raw_audit_windows_20261015_01/`。

完整检索语料尚未取得。作者仓库固定提交 `bdc1c1539d873c354f0fe42ad32f9873dca3752d` 的21份苹果示例PDF已另存，共249物理页（1份10-K、6份10-Q、14份8-K）；它们只匹配测试证据612个文档名中的1个，完整证据文档均本地可用的问题数为0，不能替代论文的145897份文档宇宙或据此报告全库Recall。原始页码、完整PDF映射、跨文件版本优先级和评测口径仍待核验；不把0起点页号或印刷页码直接当成本项目1起点物理页。初次接口超时、论文PDF本机TLS失败、Drive目录超时及缺文件404均保留，固定版本原文件下载成功也另有实测记录。

保留官方划分与指标；仅有 test 时不用于超参数选择或微调。如因主机资源采用子集，在查看模型结果前按固定种子/分层规则选取，公开子集清单、候选语料范围和任务适配，不能只保留容易样本。不同规模的检索语料不直接与论文全量数字比较。公开集没有法规时点标签时，只报告支持的组件指标，不能伪造中国法规标签或原样混合任务。

自建数据公开时记录数据卡、来源、构建/标注过程、哈希、划分、局限及可发布范围；自建集以后也可托管在 Hugging Face。目前仅取得上述公开题文件和独立示例PDF，未运行外部基准，也未向Hugging Face上传数据。公开test标签不用于训练、提示词或阈值选择；原数据卡的CC-BY-NC-ND-4.0声明随原件保留，不把本地审计视为数据许可变更或再发布。现有AI候选和模板集继续留作开发材料，不冒充正式人工基准。

## 3. 检索实验

主机配置固定：Qwen3-Embedding-0.6B 与 Qwen3-Reranker-0.6B。主实验不要求加载 4B/8B；BGE-M3 等可行对照按需顺序运行。相同 0.6B 骨干、候选深度与上下文预算下比较方法收益，另报告内存、延迟和吞吐。较大检索模型只属于将来有外部资源时的独立扩展，不能预设本机可运行。

| 配置 | 控制条件 |
| --- | --- |
| BM25 | 相同语料、中文分词和 top-k |
| BGE-M3 Dense | 固定模型 revision、编码和截断设置 |
| Qwen3-Embedding-0.6B Dense | 冻结权重；任务指令开关在开发集选择 |
| BM25＋Qwen3 Hybrid | 权重仅在开发集选择；同时比较 RRF 融合作为强基线 |
| Hybrid＋Qwen3-Reranker-0.6B | 固定相同召回候选池，评估重排收益 |
| Hybrid＋路由＋Reranker | 子库路由和查询扩展分别控制，避免混淆贡献 |

原型 02 仅输出 BM25/Dense/Hybrid/Hybrid+Routing 汇总，并默认读弱标签；新配置和逐查询明细待接入。TF-IDF 用于软件联调，不替代真实神经模型结果。

主指标为 Recall@5/10、MRR@10、nDCG@5/10；重排另报告候选池 Recall@20/50 和相同池上的排序增益。现有 MRR 按传入列表计算，正式实验须记录截断 k；分级 nDCG 尚需适配标注。对各维度分别报告均值、置信区间及错误类型。

## 4. 生成与联合核验实验

2026-10-16 最近相关工作全文核对补充：正式生成比较须覆盖逐来源/规则绑定论断的结构化强基线与通用核验强基线，并区分检索比较和固定上下文的生成约束比较。现有四模式是开发原型：共同提示已有论断及引用结构，`no_rag_diagnostic`被明确要求缺材料时不作确定回答，不能作为允许参数知识回答的闭卷QA基线。借鉴RefWalk归因格式但未实现其引用图/多视角检索时，只能报告归因适配；更大核验或修订预算须单独控制并计费。接线要求见[全文核对与强基线要求](最近相关工作全文核对与强基线要求_20261016.txt)。旧模式、结果及未冻结预算历史保留，本补充不表示新增基线已经实现或正式实验已经启动。

同日后续实现了独立的[固定上下文补充基线入口](固定上下文强基线与通用核验_20261016.txt)：逐来源归因适配和通用生成—核验—最多一次修订。当前CLI核验者与生成者使用同一配置模型，属于自核验基线，不是独立judge。pilot03原6条证据下的两个补充输出经3次真实API调用完成，未触发修订；模型自报11条支持不作质量指标。原四模式与旧产物不改，正式比较仍须冻结矩阵、核验/修订资源和独立复核流程。

后续增加可选[双源角色与日期未知检查](双源角色核验与日期未知处理_20261016.txt)：模型提出正文论断类型，程序按登记角色检查事实/规范/评价所需来源，并对公司适用主张保留缺失时点或版本信息。保留模型原verdict，另列结构与元数据问题；区间算术不是法律适用认证。本轮378项本地回归和合成回放通过，未新增真实模型请求、真实分类准确性指标或补检索；该组件尚不构成完整目标方法及正式实验验收。

将完整方法比较与组件对照分开，避免把更好的检索全部算作核验贡献。

| 对照 | 内容 | 实现状态 |
| --- | --- | --- |
| no_rag_diagnostic | 无文档检索；只诊断无证据时的回答/拒答行为，不作为主要质量对照 | 已有原型 |
| merged_corpus_generic_cited_rag | 年报与法规合并为一个检索池，全局取证；要求一般来源引用，不要求逐论断区分来源角色 | 已新增准备/生成入口，真实对照运行与冻结待完成 |
| dual_source_generic_cited_rag | 年报库与法规库分别检索并按固定配额合并；要求一般来源引用，不要求逐论断来源角色约束 | 已新增准备/生成入口，真实对照运行与冻结待完成 |
| dual_source_role_grounded_rag | 与上一组使用完全相同的检索证据；要求逐论断关联年报事实与规范性法规证据，证据链缺失时说明不足 | 已新增共用上下文与角色约束实现，真实端到端和语义核验待完成 |

主要生成比较中，合并库全局 top-k 与双库分配检索须使用相同总候选数和上下文 token 预算；双源一般引用与逐论断来源角色约束组须复用完全相同的检索结果和上下文，二者只改变生成约束。这样分别测量检索分配收益和论断—来源关系约束的增益。单库（仅年报/仅法规）作为检索诊断或消融；无检索组只用于拒答诊断。各组固定问题、语料快照、生成模型和参数。若加入核验或补检索扩展，须报告额外上下文、调用和延迟，并提供等预算对照。不能把普通引用提示包装为新算法贡献。

### 4.1 指标定义

| 指标 | 分母和含义 |
| --- | --- |
| 检索内引用匹配率 | 检索命中中有同法规/条款的唯一引用数 ÷ 唯一引用数；当前 citation_accuracy 的近似含义 |
| 引用可解析率 | 能解析到冻结语料真实来源的引用数 ÷ 唯一引用数 |
| 引用语义正确率 | 引用支持对应论断且适用时间正确的论断—引用边数 ÷ 全部边数 |
| 论断证据覆盖率 | 获得足够事实/法规支持的需要证据的论断数 ÷ 需要证据的论断数 |
| 无依据论断率 | 存在事实捏造、证据不支持或时间不适用的实质论断数 ÷ 实质论断数 |
| 虚构引用率 | 无法解析到真实法规/版本/条款的引用数 ÷ 唯一引用数 |
| 证据不足处理 | 在人工可回答/不可回答标签上报告回答覆盖率、错误接受、过度拒答和 risk–coverage 曲线 |
| 辅助 judge | faithfulness / coverage / professionalism，校准到人工核验子集 |
| 成本 | 每评价调用数、token、费用、延迟和设备内存实测 |

没有引用时引用类比例为 NA，不能以零虚构引用率证明评价可靠；仍检查无依据论断和证据覆盖。真实但未召回的引用不等于虚构引用。自报与正文相同引用去重，规范性论断同时核验事实与法规，纯事实/描述性论断按需要的证据角色核验。

输出级复核计算已有独立入口`evaluate_reviewed_generation.py`，不调用judge。它区分唯一引用存在/检索内比例、角色支持的去重引用边、上下文联合支持及所需角色引用完整性。未知给出数量、覆盖率及上下界，总体点值留空；未完成指定导出中的任一输出不静默只报已完成子集。真实4份开发回答已只生成pending协调者导出，实际尝试计分返回待独立复核、质量指标为空；正向数值演示仅为显式fixture。新入口当前不计算总体抽样权重、重复内汇总或聚类置信区间，不能当作正式分析已完成。

0–100 得分的准确性不作为当前主结论，除非另有可复现评分规则和人工参照。judge 只做辅助，不代替人工语义验证；评分失败和格式错误不得静默填零。

### 4.2 人工核验

双人独立核验至少 120 条输出，覆盖四维度、所有正式模式和错误场景。记录每层样本总量、抽样概率和权重，区分总体估计与特意采集的难例结果。核验员不见模型/模式身份，第三方仲裁；对引用、事实、时间适用性和证据不足分别标注并报告一致性。

## 5. 消融、鲁棒性和外部验证

分别移除条款切分、查询扩展、子库路由、重排、时间过滤、事实核验、法规语义核验及补检索。融合权重候选 0.3/0.5/0.7/0.9 只在开发集选择。不得以未校正的滑窗 ID 实验证明条款切分收益。

鲁棒性覆盖：缺失公司事实、移除关键条款、混入主题相近但不支持的条款、错误版本、事实/法规冲突、不可回答问题。每种扰动保留干净配对样本及人工标签，比较质量与回答覆盖，避免“全部拒答”获得表面低幻觉率。

跨模型至少两个生成模型族；检索骨干 Qwen3 与 BGE-M3 做迁移对比。条件允许时另冻结 2025 年报或新增公司外部测试，作为扩展验证，不能重新用于调参。

## 6. 统计与复现

- 检索按查询配对。每个问题的 3 次生成先在 query_id × mode 内汇总；随后按公司和问题族相关性进行配对/聚类推断，重复生成不当作独立样本，也不把维度直接视为独立公司。
- 报告绝对差值、95% 置信区间和配对效应量。公司聚类 paired bootstrap 暂定 2,000 次；辅助 Wilcoxon 使用公司级聚合结果，避免将四维度直接当独立样本。
- 预先声明主指标（引用语义正确率、论断证据覆盖率、无依据论断率）及覆盖率约束；主比较以冻结的通用核验强基线为参照。多重比较使用 Holm 校正，报告原始及校正 p 值。
- 在开发集估计方差与标注误差；样本规模不足时报告宽置信区间，不能以指定 p<0.05 作为强行达标要求。
- 固定 seed 42，记录划分清单、代码 SHA、语料/标注哈希、模型 revision/调用日期、prompt 哈希、指令、截断、候选池、设备、实际 backend、mock 状态和全部原始输出。
- API 密钥只通过环境变量/受保护配置传入，正式产物不得包含密钥。历史结果保留来源不明标记；新结果放在不同 run_id 目录，不覆盖基线。
