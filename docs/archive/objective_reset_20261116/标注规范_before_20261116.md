## 2. 检索标注对象与候选池

给定评价查询、维度、事件/适用时点和冻结语料，标注能支撑该查询的原始证据区间。将法规要求、公司事实和案例证据角色分开，按来源版本和条款定位。

候选池由 BM25、BGE-M3、Qwen3、混合检索的结果去重合并，加入人工补搜和随机负例。两名标注者不见检索器排名、分数和预标答案；对漏检来源做补充检索。召回指标须说明基于池化已判证据，不能宣称已枚举全库全部相关条款。

采用分级相关性：

| 等级 | 标准 |
| --- | --- |
| 2：直接支持 | 内容回答核心问题，证据角色与时间适用性正确 |
| 1：辅助支持 | 提供必要定义、上下文或补充依据，但不能独立支持核心结论 |
| 0：不支持 | 主题相近、错误主体/时间、角色不符或内容无关 |
| U：无法判定 | 缺失全文、适用时间未知或专业争议尚未仲裁 |

保存 query_id、query_family、dimension、event_date、doc_id、version_id、clause_no、原文字符区间、chunk_id、relevance、reason 和 annotator_id。chunk_id 用于原型兼容，原文区间用于条款/滑窗共用评测。召回主口径使用等级 2，等级 1 做辅助分析；分级 nDCG 使用 0/1/2。U 不当作负例，须处理或报告未判比例。

当前 loader 的 relevant_chunk_ids 是二值集合；正式分级 qrels 和区间映射待实现，不能将计划字段当作已支持格式。

## 3. 人工复核与一致性

1. 先在开发查询上做小规模试标，修订歧义规则，然后冻结正式规范。
2. 两名具备证券监管/公司治理理解能力的标注者对正式查询候选池独立标注，不看 AI 标签或彼此答案。
3. 二值“直接支持”使用 Cohen's Kappa，三级相关性另报告加权 Kappa；同时报告一致率、类别分布和样本量。
4. 报告全局、分维度及低一致性查询，不只报告均值。Kappa<0.6 作为本项目复核触发线，检查小样本、类别偏斜和规则问题，不能直接删除困难查询。
5. 分歧由第三名人员仲裁，保留双方原标签、理由、仲裁结果和日期。更新后的标签不用于冒充仲裁前一致性。
6. 人工尚未完成时使用明确来源标签，不自动将 AI 候选文件重命名为人工最终 gold。

至少 200 题、四维度各 50 题和 40/160 划分是历史规划目标，尚未由可用的独立双源问题族证明可行，不是冻结配额。正式问题数须先按可核验的不同事件和问题族盘点，再在查看最终测试结果前预登记实际题量和分层配额。D1–D4 仍属研究范围；缺少外部原始材料的第三方声誉等问题作为输入不足挑战，确有年报和适用法规双源证据的 D4 问题可按同一标准进入主集。现有 40 条历史检索题已参与开发，不能再次宣称为未见测试集。

开发/最终测试划分先把同一语义问题族、同一事件、相互重叠的原文证据区间及近重复意图合并成不可拆分的连通组，再按组划分；同一公司可以出现在两侧，因为 39 家年报是共同检索语料，论文不得据此声称未见公司泛化。候选文件在工作区的存在、逐行被阅读和实际用于调参是不同的暴露状态，应分别记录。最终测试题、证据标签和输出对开发/调参过程隔离；开发者不得根据最终组内容或输出调参。所有历史 40 题、先导题和已暴露种子先做公司—事件—问题族 crosswalk，不能只按题干精确去重。只有完成问题级证据复核、来源哈希校验和冻结后，题目才可称为最终测试。

结构工具与本协议的连接：`scripts/validate_dual_source_annotations.py` 保留历史默认 `legacy_company_disjoint`，以便旧记录可复查；执行当前问题留出协议时，必须显式选择 `--split-policy question_evidence_groups`。新增可选 `event_group_id` 列和可选 `question_group_links.csv`（query_id_a、query_id_b、link_type、reason、review_status），由 `src/data/evaluation_groups.py` 对显式问题族/事件ID、相同规范化题干及目标证据原文区间构建连通组。来源区间为零起点半开区间；同一PDF页上文字坐标不兼容时先保守合并并报告未知。法规文本与PDF之间的等价版本需另做规范来源 crosswalk，不可用不同文件SHA256自动断言不同法规。公共法规文档本身不会连接全部问题；相互重叠的目标法规证据会按当前保守协议归在同组，因此可能形成大组，必须如实报告题量可行性。明确标为0的无关候选不充当目标证据连接。

链接尚未复核时使用 `pending`，仅作为保守连组线索；独立复核接受或仲裁后可登记 `accepted` 或 `adjudicated`，拒绝的链接登记 `rejected` 并保留理由，不能继续作为连组边。`possible_family_overlap` 只表示可能共享意图，不能写成已确认同族。字符相似度只生成待复核线索，不自动添加语义边；低相似度、0个候选或结构检查通过都不能证明没有同义改写。工具不修改原 split，不接受gold，也不冻结测试集；还需完成历史暴露映射、独立语义复核、来源核验及组划分登记。

## 4. 双源证据样例复核

本规范的人工复核服务于“年报 PDF 与法规文件分别检索，再生成带来源依据的评价内容”这一评测目标，不要求把所有公司年报穷尽整理成结构化事实库。对每个正式评测问题，核对并记录：

- 年报证据：公司身份、报告年度/版本、PDF 物理页、原文区间或表格位置，以及该段落能支持的公司陈述范围。
- 法规证据：文件身份、条款、版本、发布日期及适用时间；事件日期未知或法规时间关系不清时标记 U/未知，不作强判。
- 问题与论断：哪些回答要点必须有年报证据、哪些规范性判断必须有法规依据，以及冻结的双库材料是否足以回答。
- 来源关系：引文是否确实支持对应论断、引用位置能否还原到输入文件、是否存在冲突或证据缺口。

区分“年报明确披露”“年报未提及”“当前候选池未找到”“明确否定”和“数据缺失”。报告未提及或抽取未命中不能当作零值、事件不存在或良好表现。年报自述只能支持“年报披露了该事项”；若问题要求确认外部事件实际发生，评测材料须另含相应原始来源。自动候选可帮助定位样例，不能直接充当最终标签。

标注时必须区分“系统可见输入”与“仅供复核者查验的外部来源”。外部来源可用于确认某项事件真实发生、核对事件日期或法规版本，也可暴露资料间冲突；应单独登记来源角色、URL、SHA256 和页/段位置，并标记 system_corpus_input=false。除非该来源实际进入冻结的年报/法规检索语料及模型上下文，否则不得把它当成输出的可引用支持，也不得因为它在隐藏复核资料中而要求模型给出该事实。若用户问题要求的外部事实或事件日期只由复核资料证明、系统输入没有载明，应标为不可回答或部分可回答，正确输出应说明输入证据不足。时间适用性实验可用外部原始来源产生隐藏的事件日期金标准，但只有把日期明确提供给模型的问题子集才能检验其按时点筛选法规的能力；不能把标注表里的隐藏日期泄漏给模型或调参过程。

## 5. 评价论断与引用核验

以实质论断为单位拆分评价，保存 claim_id、正文区间和需要的证据角色；对规范性评价建立 claim_id—fact_id—法规版本/条款链接。

分别核验：

- fact_supported：公司材料是否真实支持论断，是否存在捏造或矛盾。
- citation_exists：法规、版本、条款能否解析到真实来源。
- retrieved：引用是否在实际提供给模型的检索内容中。
- normative_supported：条文内容是否支持该规范性判断。
- temporally_applicable：在该事件日期是否适用；未知单独标注。
- evidence_status：supported / contradicted / insufficient / unresolved。
- answerability：冻结材料是否足以回答，用于评价回答或保留未判定是否恰当。

同一引用在 JSON 自报和正文重复出现时去重，但同一条款支持不同论断的边分别核验。真实但未召回的条文不是虚构引用；标题/条款号匹配不是语义支持。没有引用的输出仍核验实质论断，引用比例记 NA。

至少 120 条正式输出按维度、模式、可回答性和错误类型分层双人核验；隐藏模型/模式身份，记录随机种子、各层总量、抽样概率与权重。总体估计按抽样设计加权，难例分析另报。相同规范执行独立标注、一致性计算和仲裁。

旧版 citation_supported/fact_error 两字段保留历史含义；新增字段需扩展模板和评测加载，禁止将名称匹配自动填成全部语义支持。

已新增输出级计算入口`src/metrics/reviewed_generation.py`、`scripts/evaluate_reviewed_generation.py`，详细口径见`docs/生成评测计算口径与复核导出_20261015.txt`。它只接收有原回答/上下文哈希、实际双人输出复核索引和登记表、完整论断/引用库存及最终确认记录的导出；AI或模型标签、空表和旧来源试标不能直接计分。来源存在、是否已提供、角色支持、联合证据和必要时点分别判断；未知保留总体NA及上下界，不当负例。没有论断或引用的分母为零时指标为NA，并另看回答覆盖/过度拒答。相同论断—引用边去重，冲突性来源总结不能以“不需要证据”逃出分母。工具不认证真人、盲态或语义，不冻结测试集；总体抽样/重复汇总/聚类推断仍需后续适配。
### 2026-10-15补充：法规日期与原PDF对应关系

法规日期分别登记审议日、公告署名日、原始施行日、修订版本起算日、失效边界及过渡条件。旧`@DATE`和网页`PubDate`的原值保留；其含义未经核实，不直接用作法规生效日或网页首次公开日。日期必须附来源URL、源文件哈希及可定位引句。仅写“公布即施行”的条款须同时记录公告日期依据及推定过程，待复核，不能悄然把署名日替代公开日期。

修订决定与随附重公布文本按复合文档登记。附录可能保留更早版本的施行/废止条款；原始法规施行日不能替代本次修订的起算日。一年过渡期等条件按具体条款和事项保存，不能扩展为全部条款统一延期。只有经复核的版本区间、事件日期、适用主体和条件才能形成正式的时间适用标签；未知事件日期继续留空，不从年报年度推算。

旧文本与官方PDF对齐时，先报告原始/去空白严格匹配，再单独报告排除疑似页码后的候选结果。排除项须保留原字符区间、原引句及理由，坐标系统分别命名，不修改原文、旧偏移或期望哈希。独立纯数字行可能属于正文，不能自动删除；候选位置不能计为已接受证据。
