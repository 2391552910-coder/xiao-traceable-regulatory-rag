## PR 审阅结论与修复

建议继续保留草稿。查询与文档编码分离、冻结检查在现有验证范围内成立，但不能代表正式实验完成。

已修复两处可复现问题：

1. 消融循环加载下一个索引时仍持有旧 router/retriever，造成多个 embedding 模型同时驻留的风险。现在先解除引用并回收编码闭包引用环；弱引用回归测试验证旧索引在新索引构建前释放。
2. 数据审计把只有 `%PDF-` 文件头的截断文件计为有效 PDF。现在要求严格解析且至少一页，分别记录文件头、解析状态和公司/年度核验；解析成功仍不等于年报身份或事实已验证。

新增模型修复已经完成有限验证：本地 reranker 改用 AutoModelForCausalLM，以最后 token 的 yes/no 二分类概率评分；左侧 padding、模板预留长度、只计算末 token logits 和关闭 KV cache 已接入。embedding/reranker 共享顺序加载器，后者惰性加载；切换前释放旧权重，查询缓存以指令与文本共同作为键。CPU batch=1，两个默认模型均保持 0.6B，revision 已固定。运行结果保存实际模型 revision、dtype、设备、长度和权重切换事件。

对照 [Qwen 官方 Transformers 用法](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) 和 [Transformers 4.51.3 Qwen3 源码](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen3/modeling_qwen3.py) 做了真实小样本检查：2 个合成文档、2 个查询，CPU，max_length=256。封装概率与直接 forward 的 binary log_softmax 一致，最大绝对差约 2.98e-7；弱引用验证模型切换后旧权重对象释放。运行耗时 65.12 秒（包括首次权重获取/加载，不是查询延迟），进程峰值 RSS 4,542,884 KiB，约 4.33 GiB。默认配置的 8192 长度峰值未测，不能外推该内存数字。

模型 revision：Embedding `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，Reranker `e61197ed45024b0ed8a2d74b80b4d909f1255473`。实际 dtype 分别为 float32 和 bfloat16，运行环境 torch 2.6.0+cpu、transformers 4.51.3、sentence-transformers 3.1.1。

完整证据在 `real_model_smoke/`，包含向量、run.json、逐文件指令说明与哈希。`model_loading_reproduction.json` 是修复前的负面复现，保留为历史。另以 TF-IDF 跑通 40 道已开发问题、5 个配置的离线管线（200 行），结果为开发联调，不是 Qwen 正式质量实验。

这些验证不代表监管语义质量提升，也不是微调或整套论文实验。仍需正式标签、完整数据、默认长度资源测量和路由召回逻辑修正。新顺序加载器面向单管线顺序调用，不声明支持并发请求隔离。
