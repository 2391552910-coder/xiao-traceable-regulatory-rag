# 检索评测协议与人工复核

## 当前可以确认的范围

检索与消融统一读取 `data/annotation/retrieval_queries_gold.csv`，包含 40 条查询、226 条正例标注、
219 个不同证据块。查询分布为 D1/D2/D3/D4 = 10/10/11/9。
语料为 319 篇文本（法规/历史节选 88、处罚 212、通报 19），历史兼容切分得到 7,899 块。

当前基准 ID 为 `regulatory-gold-ai-20261013`，状态为 **provisional / development_only**。
冻结保证实验读到同一份数据、标注轮次和切分实现；它不认证 AI 标签的正确性。
40 条查询已用于开发，不应通过事后划分就宣称得到未见过的独立测试集。

结构校验确认：查询/文档/块 ID 无重复，正例非空、数量一致、引用均可定位；
所有 gold 标签均能从双通道标注与分歧仲裁记录重建。
未确认候选池覆盖了所有相关证据，也未记录独立人工复核。

## 审计发现

- 56 个不同正例块的存储条款号来自正文中的法规引用，而非所在条款标题。
- 7 个不同正例块被历史 2,000 字上限截断；与上一项合并为 62 个不同块。
- 7 组文档正文完全重复，需明确去重规则；旧 gold 不在本次操作中自动修改。
- Q26、Q34 两路标签均为单一类别，Kappa 未定义，不能写成 1.0。
- 剩余 38 条查询逐查询平均 Kappa 为 0.746874；历史报告约 0.760 包含了两个人为记作 1.0 的值。
- Q09/Q12/Q13/Q16/Q17/Q24/Q31/Q33/Q35 的 Kappa < 0.6，优先复核。

原 `kappa_report.csv` 与 gold CSV 均保留，新的审计 JSON 提供重算值、分歧追溯和结构问题清单。
新增的源文本跨度与标题标志不改变历史 C ID、文本或标签；不能据此宣称已经修好了完整条款切分。
`owner_clause_no` 仅为自动推断的定位线索，人工复核必须查完整原文。

## 可复现运行

```bash
pip install -r requirements-eval.txt
python scripts/audit_benchmark.py
python experiments/02_retrieval_evaluation.py --backend tfidf
python experiments/04_ablation_study.py --backend tfidf
python -m pytest tests/test_benchmark.py tests/test_smoke.py -q
```

每次运行默认创建新的 `results/runs/<run>/` 目录，已有结果不能被覆盖。
也可用 `--output results/runs/my_run/retrieval_eval.csv` 指定新位置。
查询、语料、切分器或标注轮次与冻结摘要不符时，运行在加载模型之前停止。
GitHub Actions 使用轻量依赖检查冻结基准与回归测试，不下载模型、不调用 API；
工作流在本次改动推送后才会触发。

输出包括汇总 CSV、逐查询排名与命中、分维度指标、成对 bootstrap 95% CI、审计 JSON、运行 JSON。
运行记录包含真实后端与分词器、配置（密钥脱敏）、软件版本、Git revision/dirty 状态、代码与结果摘要。
TF-IDF 后端的模型名记录为 TF-IDF，不将配置中的 Qwen 名称当成实测模型。
根目录 `results/retrieval_eval.csv` 等旧文件没有同等运行记录，不应与新结果混用。

真实模型需安装 `requirements.txt` 并配置本地/远端服务，再运行例如：

```bash
python experiments/02_retrieval_evaluation.py --backend qwen --device cpu
# 只有显式传入 --rerank，才加载本地或远端 reranker
python experiments/02_retrieval_evaluation.py --backend qwen --device cpu --rerank
```

检索配置固定为 BM25、Dense、Hybrid、Hybrid+QueryExpansion、Hybrid+Routing。
QueryExpansion 单独成组；+Reranker 单独报告，避免把精排和融合/路由效果混为一谈。
当前路由实现是全库召回后进行维度候选过滤，运行对照保留该行为；
不能将结果解释为已实现了独立子库的完整召回。

## 指标定义与消融限制

以同一批查询做查询宏平均，并单独报告四维度分数。主指标是 Recall@k、MRR@k、nDCG@k、Hit@k；
CSV 为兼容保留 `mrr` 列名，运行 JSON 明确它的截断深度。
置信区间按查询成对重采样，默认 seed=42、2,000 次；它描述当前开发基准上的不确定性，
不代替独立测试，也不证明方法必然优于基线。

条款组按 gold C ID 精确匹配。滑窗 W ID 不等于 C ID，不能直接使用集合交集。
滑窗组在同一文档中累计源文本跨度；覆盖某 gold 可见证据至少 50% 才命中，重叠跨度去重。
Recall 统计命中的 gold 单元比例；MRR 使用首次满足覆盖阈值的检索块 rank；
nDCG 的某 rank 只有首次覆盖新的 gold 单元才有一个二元增益。
同一窗口命中多个 gold 单元可提高 Recall，但该 rank 的 nDCG 增益仍只计一次。

这一跨切分口径是**已标注证据的覆盖代理**，不是对滑窗支持某结论的语义认证。
正式比较切分方法时，还需独立标注窗口的语义相关性，并报告覆盖阈值敏感性。
不能仅据代理分数得出条款切分或滑窗切分更好的论文结论。

## 从开发基准到人工认证基准

1. 审计脚本导出 667 条原候选/补标/正例候选的 `human_review.csv`，不展示原标签。
   实验 02 还将五个检索方法的 top-k 合并进候选池，以发现旧候选池的漏标。
2. 两位真人分别使用独立副本，在 `human_label` 填 0/1，记录 `annotator` 与依据。
   直接相关和部分相关的口径应按标注规范固定；不能因某方法命中就自动加为正例。
3. 重点核对上述结构问题、低一致性查询、法规生效/废止版本、相同文本的重复文档，
   并参照 `rounds/suggested_supplements.md` 补充候选。对截断块查完整原文。
4. 如果修正切分方式，应基于文档与源跨度重新定位证据，重新审核标签；不能仅按新编号替换旧编号。
   记录文档、条款、证据文本摘要和标签变更原因，保留历史版本。
5. 重新计算人工一致性并由第三人仲裁分歧；再建立单独的人工基准与版本清单。
   本轮代码不会把填写后的任意 CSV 自动认证成人工 gold。
6. 新增独立查询用于最终测试，提前冻结查询、标注、模型与参数；合成集和现有 40 条用于开发/选型，
   同一原条款的不同合成改写不得跨训练/测试集合。正式测试结果不再用于反复调参。

更新开发基准前保存旧标注和清单，使用新版本号，例如：

```bash
python scripts/audit_benchmark.py --freeze regulatory-gold-ai-next-version
```

同一基准 ID 不允许悄悄更换数据；冻结后再次运行审计与回归测试。
