# 实验设计与流程

方案版本：2026-11-16。当前实验围绕年报四维度知识库、gold evidence 与 gold chunk、本地 embedding 和 rerank 比较，以及切片和检索策略对年报问答的影响。目标见[项目任务与验收](项目任务与验收.md)，字段见[标注规范](标注规范.md)。[修订前方案](archive/objective_reset_20261116/实验设计与流程_before_20261116.md)仅作历史记录。

模型已本地部署、年报和法规已采集，这是本轮工作的起点。当前文档定义待实施实验，不表示标注、知识库验收和下列对照均已完成。

## 1 研究问题

1. 四维度事实抽取是否准确，原文来源是否完整，人工审查范围内的知识覆盖如何。
2. 相同语料和问题条件下，不同 embedding 的召回表现与成本有何差异；相同候选池下，重排的排序表现与成本有何差异。
3. 切片、检索及重排设置对证据命中、多证据完整性和问答质量的影响分别多大。
4. 检索改进能否传递到答案正确性与证据支持，哪些问题仍因解析、抽取或生成失误而失败。

不预设混合检索、某个模型或更长上下文一定更好。模型组件组合本身不自动构成算法创新；论文贡献及表述随实际方法和结果确定。

## 2 数据冻结与知识库

先从既有资料生成本次语料清单，分开统计物理文件、副本、去重文档、公司、年度、法规版本、解析成功文档与可检索块。历史清单、目录加载数和不同索引粒度不可直接相加。数据与模型清单（本地文件）记录当前核验范围：39 家公司、39 份 2024 年年报、9,999 个物理页；监管 TXT 目录 319 份，其中清单内 315 份包括 84 份法规、212 份处罚和 19 份公告，另有 4 份历史额外文件，不能称为 319 部法律。

每份年报保存来源与文件哈希、公司、报告年度、页数和解析状态；法规另存文种、来源角色和版本日期，未知日期保持未知。本次正式语料仍须完成范围、重复与完整性审查并冻结。

知识库包含原文证据和四维结构化事实。D1 信息披露质量、D2 董事会治理有效性、D3 内部控制与合规性、D4 第三方声誉均按年报明确记载抽取。D4 不补造未出现在年报中的评级或舆情。每条事实通过 evidence_id 回到原文页与区间，数值保留单位和口径，表格保留必要表头与跨页关系。

事实问答默认在公开问题给出的公司和年度范围内检索年报；公司或年度未给出时，不能使用隐藏标签补齐过滤条件。所有方法使用同一可见过滤条件。法规需求作为题目类型标注，法规辅助问答独立形成子集。

## 3 gold 与数据划分

先在冻结文本快照上标注原文证据单元，再派生各切片方案的 gold chunk 映射。证据单元可以是一段文字、带表头的表格单元组合或跨页片段。每个必需 evidence_group 对应一个必需答案要点，组内以 OR 关联替代 support_option，每个 option 内以 AND 关联必要 evidence_id 或 span。任一 option 完整即该组命中；组覆盖分母为必需组数，全题完整成功要求所有必需组命中。必须完整包含核心必要区间，同页或任意字符重叠不能替代支持判定。

候选来源覆盖 BM25、向量、混合检索与各切片方案，并补充人工原文查找和负例。真实人工确认正式证据、答案及相关性；AI 预标结果单独保存。对测试集和难例建议独立复核，实际执行人数与覆盖率按记录说明。

按问题族、同一事件及重叠目标证据建立连通组。开发集用于选择模型、融合参数、切片参数和提示；测试集冻结前确定实际题量、各维分布、答案类型、可回答性、组数及随机种子。测试标签、参考答案和输出不用于选择配置；若查看测试后改方法，另建新测试版本，旧结果按开发或探索报告。当前共享语料与历史暴露不支持未见公司泛化主张。

题量以人工审查可形成的有效组数及成本为依据，不预设四维必须等量。若 D4 可回答样本较少，公开分布和限制；证据不足题另列，不通过补写外部事实凑数。抽取质量评测单独保存人工审查样本及其穷尽标注范围，不能用检索 gold 代替全库抽取评价。

## 4 固定设置

| 因素 | 方案 |
| --- | --- |
| 段落标题切片 C2 | 单块上限 512 tokens；仅长段拆分时设置 64 tokens 重叠 |
| 固定窗口切片 C1 | 512 tokens 窗口、64 tokens 重叠；与 C2 使用同一登记的切片 tokenizer |
| 父子组织 C3 | 复用 C2 子块，增加章节父级关联；检索返回子块，问答阶段按父级扩展 |
| 检索截断 | K = 5、10、20；固定切片的主指标在开发阶段选定，测试前登记 |
| 跨切片主口径 | 固定 token 预算下的证据组覆盖和完整证据成功率；块级 K 指标作为辅助 |
| 重排候选 | 各重排对照共用同一逐题 Top-50 候选池，保存原始分数和顺序 |
| 向量与融合 | 统一归一化和相似度口径；混合检索采用 RRF，参数仅由开发集选择 |
| 生成 | 同一生成器、模型版本、提示、解码设置和最终上下文 token 预算 |
| 资源 | 同一设备、精度、批量与运行条件；冷启动、建库和查询延迟分别计量 |

切片 token 与模型 token 的计数器均登记。不同模型 tokenizer 可以不同，输入最大长度必须容纳实际查询、指令和块文本；溢出率和截断位置留痕，不能用静默截断给某个模型更少证据。大表格或跨页证据按预先规定的解析规则处理，不能查看测试答案后补表头。

C3 与 C2 使用相同子块，检索排名无需重复计算，不能声称 C3 提升子块召回；其有效比较是父级扩展对问答上下文的影响。父级扩展使用相同最终 token 预算，公开去重、截断及实际证据覆盖。重叠块去重与预算裁剪规则在测试前冻结。

## 5 分阶段实验矩阵

| 阶段 | 改变因素 | 固定条件 | 输出 |
| --- | --- | --- | --- |
| E0 知识库质量 | 四维字段与来源类型 | 固定抽取流程、独立人工审查样本 | 字段正确性、来源完整率、样本内覆盖和错误类型 |
| E1 embedding | Qwen3-Embedding-0.6B、BAAI/bge-m3 | C2、相同过滤、无重排 | 逐题排名、检索指标和资源成本 |
| E2 rerank | 不重排、Qwen3-Reranker-0.6B | 开发选定 embedding；固定 BM25 与 dense 融合后的同一 Top-50 候选 | 候选池召回、重排后排序、增量延迟和显存 |
| E3 切片和检索 | C1/C2 × BM25/dense/hybrid × 重排关闭/启用 | 固定开发选定模型和参数，共 12 个独立检索条件 | 配对消融及固定预算完整证据覆盖 |
| E4 问答 | 无检索、固定基线、开发选优配置、oracle evidence 诊断；C2 与 C3 配对 | 同一问题、生成器、提示及上下文预算 | 答案、证据支持、引用定位、父级扩展效果和成本 |

本地 Qwen 两个 0.6B 模型和 BGE-M3 已有历史 GPU 运行记录，正式实验仍须登记本次权重版本、设备及配置。BGE-Reranker-v2-M3 尚未核实本地可用，仅可在实际就绪后作为可选额外重排模型，不把重新部署设为本轮前置任务。

开发集用于选择参数和后续阶段固定的模型；冻结测试集仍完整报告 E1 两个 embedding、E2 重排开关，以及 E3、E4 的预登记对照，不能只报告开发选优条件。不能看测试分数后追加有利配置。E2 使用缓存的同一候选池。E3 对每种切片与检索方式分别缓存候选，其重排开关复用对应候选，不能把候选池差异解释为纯重排收益。

纯年报子集用于主问答结果，法规辅助子集独立报告。oracle evidence 将人工 gold 证据提供给生成器，仅诊断正确证据已给出时的生成能力，不能与实际检索性能混报。无检索不注入隐藏结构化答案。若比较原文库与四维结构化检索库，单列为开发选定的知识组织对照，保持原文范围和可见字段一致。

## 6 分层评价

### 6.1 抽取和知识库指标

在人工审查范围内报告字段精确匹配、实体或集合 F1、数值及单位正确性，以及各维错误分布。抽取 Precision、Recall 的分母来自该样本明确枚举的预测事实与应抽取事实，不以整份年报的不完整参考作为完整金标准。

来源完整率衡量事实是否具有有效且可还原的证据关联；原文位置有效不等于事实语义正确。知识覆盖率只对审查范围内的应收录知识计算，另报维度、公司及年度的结构覆盖，不称为全库语义覆盖率。

### 6.2 检索指标

固定切片比较报告 Hit@K、MRR@K、已判证据单元 Recall@K 和答案要点证据组完整覆盖率。命中按冻结的原文区间和语义映射规则判断，相同证据去重；跨块必要证据按 Top-K 并集检查完整性。

跨切片主要在相同可用上下文 token 预算下比较证据组覆盖和全题完整证据成功率，同时报告实际供给 token、检出块数与块长度分布，避免大块凭覆盖更多文字获得虚假优势。块级 K 指标作为辅助，不将不同粒度的块 Precision 直接当作语义优劣。

池化标签不完整时，Recall 分母为已判相关证据，带“池化已判”限定。未判候选与 U 保持未知，公开各系统 Top-K 未判比例；Hit、MRR 也说明基于已确认相关证据的限制。只有评价截断内候选具备充分判定覆盖，才报告 Precision@K 和分级 nDCG@K，预先固定相关性 gain、去重与 IDCG 规则。

### 6.3 问答指标

参考答案和答案要点在生成前冻结。字段、名单、日期题报告 EM 或字段 F1；数值题先登记单位换算、小数及允许误差，报告容差内正确率。综合答案按冻结要点评分，不用字符串相似度代替事实判断。

实质要点的证据支持率、引用原文定位有效率及引用语义支持分别报告；引用 ID 存在不代表内容得到支持。可回答题与证据不足题分别报告正确回答、恰当保留和过度拒答。自动 judge 保留模型、提示和输出，单列未经人工校准的限制，不能冒充人工 gold。

### 6.4 成本与统计

报告建库时间、索引体积、embedding 与 rerank 查询延迟、峰值显存或内存、上下文 token 与生成成本；说明预热、重复次数和测量边界。重复计时不增加独立问题样本量。

按问题与证据连通组保留配对，并处理公司内相关性；具体聚类或重采样方案在测试前冻结，据此报告差值与置信区间，小样本只作描述。预登记主指标及主要对照，其余作为补充。失败与缺失纳入分母或说明有效分母，不能只保留成功输出；阈值、统计脚本和种子在查看测试结果前固定。

## 7 运行产物与完成条件

每次运行保存语料和文本快照哈希、切片方案、索引版本、模型权重与 revision、输入指令、过滤、候选池、排名、gold 映射、答案与上下文、错误状态、计时及汇总脚本。输出使用新的 run_id，保留历史文件。

完成顺序为清单核验、四维建库、gold 标注及划分、开发选择与方案冻结、测试运行、分层统计与论文补写。没有 gold 时可以做流程检查和开发诊断，正式 gold 指标列为待测；新目标结论仅由相应真实运行支持，历史双源生成评分不能替代本轮检索和问答测试。
