# 实验设计与流程

任务版本：2026-10-13。总目标是完成支撑大论文的小论文算法与实验，以中科院二区计算机类期刊为投稿目标。任务边界见[项目任务与验收](项目任务与验收.md)。

以下区分已有原型与正式研究设计；计划中的新配置、指标和数据结构尚未全部实现。不能将本文件直接作为已完成实验的论文结果部分。

## 1. 研究问题与方法假设

- **RQ1**：在相同语料与标注下，条款切分、维度路由、Qwen3 检索/重排是否改善监管证据的召回与排序？分析各组件以及成本。
- **RQ2**：年报和法规双库分别检索后用于生成，是否比单库检索或不带引用的生成更能提供有原文支持、来源可定位的评价内容？
- **RQ3**：切分、查询扩展、双库召回、融合、重排和适用时间过滤各自贡献多大？
- **RQ4**：在年报证据缺失、法规不适用或版本错误、证据冲突及不可回答场景下，系统能否避免无依据断言并正确说明证据不足？

研究假设由人工核验的双源证据样例检验，不要求预先将全部年报整理成事实表。评价论断逐项检查年报证据是否支持公司相关陈述、法规证据是否相关且在目标时点适用、引用是否能回到冻结来源。

以上是待检验假设，不预设效果方向、引用正确率或 p 值。相关工作与差异审查见[研究依据与微调决策](研究依据与微调决策.md)。

## 2. 数据与划分

### 2.1 监管语料

清单内 315 篇对应 7,840 块，其中有条款号 7,525 块；当前 loader 扫描全部 txt，实际为 319 篇、7,899 块。DOC001–DOC003 是早期节选，DOC004 已替换为内控规范全文并被 Q22 gold 使用，不能将四个文件一律删除。

正式冻结前：登记 DOC004、隔离节选、审计重复与正文完整性；建立来源、版本、发布日期、生效/失效日期、正文哈希和字符区间。保留历史版本用于事件时点判断，不能把“最长文本”或“当前有效”等同于“在 2024 年适用”。

法规、处罚决定与案件通报分别记录证据角色。案例不能直接充当普遍法规；处罚正文中出现“第 X 条”可能只是援引其他法律，不自动等同于该文书的结构边界。条款号解析率也不等同于完整条款切分正确率。

### 2.2 检索标注

当前 40 条弱标签为 `weak_auto`；40 条 AI 双通道仲裁候选为 `ai_dual_pass_adjudicated`，共 226 个相关块。平均逐查询 Kappa 约 0.760 属于 AI 通道一致性，不能写成双人人工一致性或全局 Kappa。

规划扩至至少 200 条，四维度各至少 50 条。按语义问题族分出约 40 条开发和 160 条最终测试；现有已反复查看的 40 条仅作开发/回归素材。使用多检索器候选池、人工补搜和随机负例，全部由两名人员独立复核并仲裁。协议见[标注规范](标注规范.md)。

条款与滑窗比较必须映射到统一的原文字符区间/证据单元。不能以 `C` 和 `W` 块 ID 相等计算命中；碎片只有满足标注的必要证据覆盖条件才算命中。

### 2.3 年报、法规双库与生成评测

年报 PDF 与法规文件都是系统直接输入的文档。导入时分别登记来源、主体/文档身份、报告年度或法规版本及已知日期；解析文本，扫描页按需 OCR；切分时保留 PDF 物理页、文本字符区间和原文哈希等来源坐标，再分别建立年报库和法规库索引。用户问题触发两路检索：年报库提供公司证据，法规库提供相关且适用的条款；生成内容将论断与两类来源分别关联，并在任一证据链不足时显式说明。

39 家 2024 年报是先导文档集合，不等于 39 个独立评测样本，也不支持对全部 A 股作总体推断。正式评测按公司分组开发与测试，同一公司的不同年度也须留在同一组，降低披露措辞和事件重复造成的泄漏。法规语料须保留版本、发布日期、生效/失效日期和适用时间信息；事件日期未知时不能强行判定法规适用。

评测标注单位是问题及其双源证据：评价问题、需要回答的论断要点、支持这些要点的年报页/段、相关法规版本/条款、各引用支持关系，以及可回答性/证据不足标签。人工复核用于评估检索与生成是否找对、用对和引对来源；不要求穷尽抽取所有公司事实。自动候选可辅助发现评测段落，但不得直接作为 gold。年报未提及不能标成事件不存在；年报自述支持的是“年报披露了该事项”，若要断言外部事件确实发生，需在系统输入中有相应外部原始证据。

### 2.4 合成与微调数据

已有 600 条模板查询和 3,600 个 Rerank 对，仅用于联调和探索。query_id 不跨 split，但正例条款及法规跨组，不能据此宣称无泄漏。

如开展微调，先按法规族/同源条款划分，再合成问题、挖难负例和去重；最终测试查询及标签保持隔离。知识库作为共同检索语料不等于允许使用测试监督。另设跨法规泛化测试，具体方案见[微调决策](研究依据与微调决策.md)。

### 2.5 自建主集与公开外部验证

主实验采用自建双源评价集，以年报 PDF、历史适用法规文件和问题级人工证据标签检验双库检索及引用生成。公开基准只补充验证其标签实际支持的检索或证据归因能力，不能以一般金融 QA 结果替代中国公司自律评价验证。

初筛 [LOFin / Open-domain Financial QA](https://huggingface.co/datasets/HYdsl/Open-domain_Financial_QA)，来源为 [HiREC 论文](https://aclanthology.org/2025.findings-acl.855/)及[官方代码/数据入口](https://github.com/JaeyoungChoe/LOFin-bench-HiREC)。这是候选而非已完成外部实验：须核验全文可取得性、证据页码映射、使用条件、字段一致性与本机文本检索成本，再决定使用；当前卡片提供 test 与页码证据，viewer 存在字段不一致错误，以原始文件审计为准。

保留官方划分与指标；仅有 test 时不用于超参数选择或微调。如因主机资源采用子集，在查看模型结果前按固定种子/分层规则选取，公开子集清单、候选语料范围和任务适配，不能只保留容易样本。不同规模的检索语料不直接与论文全量数字比较。公开集没有法规时点标签时，只报告支持的组件指标，不能伪造中国法规标签或原样混合任务。

自建数据公开时记录数据卡、来源、构建/标注过程、哈希、划分、局限及可发布范围；自建集以后也可托管在 Hugging Face。当前没有下载公开基准或向 Hugging Face 上传数据。现有 AI 候选和模板集继续留作开发材料，不冒充正式人工基准。

## 3. 检索实验

主机配置固定：Qwen3-Embedding-0.6B 与 Qwen3-Reranker-0.6B。主实验不要求加载 4B/8B；BGE-M3 等可行对照按需顺序运行。相同 0.6B 骨干、候选深度与上下文预算下比较方法收益，另报告内存、延迟和吞吐。较大检索模型只属于将来有外部资源时的独立扩展，不能预设本机可运行。

| 配置 | 控制条件 |
| --- | --- |
| BM25 | 相同语料、中文分词和 top-k |
| BGE-M3 Dense | 固定模型 revision、编码和截断设置 |
| Qwen3-Embedding-0.6B Dense | 冻结权重；任务指令开关在开发集选择 |
| BM25＋Qwen3 Hybrid | 权重仅在开发集选择；同时比较 RRF 融合作为强基线 |
| Hybrid＋Qwen3-Reranker-0.6B | 固定相同召回候选池，评估重排收益 |
| Hybrid＋路由＋Reranker | 子库路由和查询扩展分别控制，避免混淆贡献 |

原型 02 仅输出 BM25/Dense/Hybrid/Hybrid+Routing 汇总，并默认读弱标签；新配置和逐查询明细待接入。TF-IDF 用于软件联调，不替代真实神经模型结果。

主指标为 Recall@5/10、MRR@10、nDCG@5/10；重排另报告候选池 Recall@20/50 和相同池上的排序增益。现有 MRR 按传入列表计算，正式实验须记录截断 k；分级 nDCG 尚需适配标注。对各维度分别报告均值、置信区间及错误类型。

## 4. 生成与联合核验实验

将完整方法比较与组件对照分开，避免把更好的检索全部算作核验贡献。

| 对照 | 内容 | 实现状态 |
| --- | --- | --- |
| no_rag | 无文档检索，作为生成参照 | 已有原型 |
| single_corpus_rag | 仅检索年报或仅检索法规 | 双库评测所需的新对照 |
| naive_rag | 年报与法规检索内容注入，不要求逐项引用 | 已有原型，需接双库输入 |
| dual_source_cited_rag | 分别检索年报公司证据和适用法规，生成带逐项来源引用的内容 | 本文目标系统，端到端待实现与验证 |

各生成对照固定输入问题、双库文档快照、生成模型、参数与上下文预算；消融单独关闭年报检索、法规检索、重排或来源引用，区分检索增益与引用生成增益。若加入核验或补检索扩展，须报告额外上下文、调用和延迟，并提供等预算对照。不能把普通引用提示包装为新算法贡献。

每个公司/维度/模式生成 3 次，保留 repeat_id、失败/重试和原始响应；每个生成论断关联年报证据、法规证据或明确的证据不足状态。至少用两个独立模型族验证生成端迁移；主生成模型与 judge 分开配置，具体版本在正式运行前冻结。当前 03 实际复用生成客户端做 judge，需先改造。

### 4.1 指标定义

| 指标 | 分母和含义 |
| --- | --- |
| 检索内引用匹配率 | 检索命中中有同法规/条款的唯一引用数 ÷ 唯一引用数；当前 citation_accuracy 的近似含义 |
| 引用可解析率 | 能解析到冻结语料真实来源的引用数 ÷ 唯一引用数 |
| 引用语义正确率 | 引用支持对应论断且适用时间正确的论断—引用边数 ÷ 全部边数 |
| 论断证据覆盖率 | 获得足够事实/法规支持的需要证据的论断数 ÷ 需要证据的论断数 |
| 无依据论断率 | 存在事实捏造、证据不支持或时间不适用的实质论断数 ÷ 实质论断数 |
| 虚构引用率 | 无法解析到真实法规/版本/条款的引用数 ÷ 唯一引用数 |
| 证据不足处理 | 在人工可回答/不可回答标签上报告回答覆盖率、错误接受、过度拒答和 risk–coverage 曲线 |
| 辅助 judge | faithfulness / coverage / professionalism，校准到人工核验子集 |
| 成本 | 每评价调用数、token、费用、延迟和设备内存实测 |

没有引用时引用类比例为 NA，不能以零虚构引用率证明评价可靠；仍检查无依据论断和证据覆盖。真实但未召回的引用不等于虚构引用。自报与正文相同引用去重，规范性论断同时核验事实与法规，纯事实/描述性论断按需要的证据角色核验。

0–100 得分的准确性不作为当前主结论，除非另有可复现评分规则和人工参照。judge 只做辅助，不代替人工语义验证；评分失败和格式错误不得静默填零。

### 4.2 人工核验

双人独立核验至少 120 条输出，覆盖四维度、所有正式模式和错误场景。记录每层样本总量、抽样概率和权重，区分总体估计与特意采集的难例结果。核验员不见模型/模式身份，第三方仲裁；对引用、事实、时间适用性和证据不足分别标注并报告一致性。

## 5. 消融、鲁棒性和外部验证

分别移除条款切分、查询扩展、子库路由、重排、时间过滤、事实核验、法规语义核验及补检索。融合权重候选 0.3/0.5/0.7/0.9 只在开发集选择。不得以未校正的滑窗 ID 实验证明条款切分收益。

鲁棒性覆盖：缺失公司事实、移除关键条款、混入主题相近但不支持的条款、错误版本、事实/法规冲突、不可回答问题。每种扰动保留干净配对样本及人工标签，比较质量与回答覆盖，避免“全部拒答”获得表面低幻觉率。

跨模型至少两个生成模型族；检索骨干 Qwen3 与 BGE-M3 做迁移对比。条件允许时另冻结 2025 年报或新增公司外部测试，作为扩展验证，不能重新用于调参。

## 6. 统计与复现

- 检索按查询配对，问题族相关性通过分组重采样处理。生成先在公司×维度×模式内聚合 3 次重复，再以公司为聚类单位比较；重复不是独立公司样本。
- 报告绝对差值、95% 置信区间和配对效应量。公司聚类 paired bootstrap 暂定 2,000 次；辅助 Wilcoxon 使用公司级聚合结果，避免将四维度直接当独立样本。
- 预先声明主指标（引用语义正确率、论断证据覆盖率、无依据论断率）及覆盖率约束；主比较以冻结的通用核验强基线为参照。多重比较使用 Holm 校正，报告原始及校正 p 值。
- 在开发集估计方差与标注误差；样本规模不足时报告宽置信区间，不能以指定 p<0.05 作为强行达标要求。
- 固定 seed 42，记录划分清单、代码 SHA、语料/标注哈希、模型 revision/调用日期、prompt 哈希、指令、截断、候选池、设备、实际 backend、mock 状态和全部原始输出。
- API 密钥只通过环境变量/受保护配置传入，正式产物不得包含密钥。历史结果保留来源不明标记；新结果放在不同 run_id 目录，不覆盖基线。

当前 05 会覆盖重复生成记录，06 只实现检索图；修复和补齐前，不据此宣称已完成正式统计与全部出图。结果清单见[实验产物说明](../results/README.md)。
