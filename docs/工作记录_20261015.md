# 工作记录 2026 年 10 月 15 日

本记录汇总 Windows 本地实际执行的结果、当前限制及后续排期。日期使用北京时间，文件与结果以本次核对的本地产物为准。

## 当前任务

系统接收年报 PDF 与法规文件，登记身份和版本后解析、切分、索引。用户提出评价问题时，分别检索年报公司证据与法规依据，再生成带来源引用的回答。年报事实候选仅可辅助定位和问题级评测，不要求先穷尽整理全部公司事实。

## 已实际完成

GPU batch 4 尝试曾发生 CUDA 显存不足，失败记录保留；batch 1 重试约耗时 77 分 9 秒。该耗时包含建库和一次问题调用，不是单次在线检索延迟。CPU 与 GPU 两次重排设置不同，不能据此报告严格加速比。

两次答案文件 SHA256 均与各自 `run.json` 一致。来源编号解析只能说明编号对应本次上下文，不能证明引句支持论断或法规适用。法规文本没有物理 PDF 页码时不虚构页码。

### GPU 默认配置和小规模双模型检查

本地 Embedding 与 Reranker 已默认采用 CUDA、float16、batch 1；GPU 入口检查 CUDA，并拒绝本地 CPU 神经模型配置，不自动回退。PDF 解析、BM25、文件管理和当前矩阵计算仍有主机 CPU 运算。真实生成采用配置的 API，不据本机 CUDA 状态宣称生成模型也在本机运行。

在两个 Qwen 0.6B 模型同时驻留 GPU 时，已用前次运行保存的 10 个来源片段完成小测，并用合成长输入检查 Reranker 的 3072 token 上限。

- 实际嵌入维度为 1024，向量和重排分数有效。
- PyTorch 峰值分配为 3511.6 MiB，峰值保留为 3942.0 MiB；不是整机显卡总占用。
- 小测耗时约 38.9 秒，状态为 `passed`。
- 新半精度双模型配置尚未完成全量质量实验，不能与此前 float32、关闭重排的结果混为同一设置。

### 生成配置和回归

本地新增项目根目录 `.env` 自动加载，支持 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`，已有进程环境变量优先。

截至本记录，程序已读取到非空的密钥、URL 与模型配置；尚未发起真实生成 API 请求验证连通。默认仍为 `mock: true`，真实生成须显式使用 `--real-llm`。`mock` 使用确定性模板模拟最后的回答；此前的检索和向量计算是真实执行，生成内容不能用来评估大模型回答质量。

相关回归最新一次为 **26 passed，1 warning**，涵盖 `.env` 优先级、CUDA 无自动回退、编码指令、重排输入、检索作用域与文档来源等。测试和小测均不等于正式质量验收。

本次发布不包含 `.env`、密钥内容或真实 API 响应。
