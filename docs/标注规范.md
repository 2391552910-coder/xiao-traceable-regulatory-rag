# 标注规范

版本：2026-11-16。用于年报四维度知识库抽取评价、gold evidence 与 gold chunk 测试集，以及年报问答参考答案建设。2026-10-29 停止新增人工标注的旧安排已被当前任务取代，[旧规范](archive/objective_reset_20261116/标注规范_before_20261116.md)保留供追溯。

本规范说明待建设的数据与流程，不表示现有 CSV、评测器或标签已支持所有字段。正式使用前须检查实现与协议一致。AI 可生成候选，正式 gold 的答案、证据及相关性均须真实人工确认；未确认记录保持候选状态。

## 1 标注对象和维度

来源是本次冻结年报文本快照与对应 PDF 原页；法规只在题目需要定义或规范依据时另标。记录 D1 信息披露质量、D2 董事会治理有效性、D3 内部控制与合规性、D4 第三方声誉。问题可关联多维，并登记一个主维度。

只标记年报实际披露内容。D4 的评级、评价、荣誉和负面事件须有明确年报证据，不能从外部常识补写。区分明确披露、明确否定、未披露、解析失败和冲突待核实。缺失不能填零，未提及不能解释为事件不存在；公司自述与第三方评价按来源角色区分。

## 2 与切片无关的 gold evidence

原文证据使用稳定 evidence_id。跨页或不连续证据以多个 span 组成同一语义单元。

| 字段 | 含义 |
| --- | --- |
| doc_id 与 source_sha256 | 冻结文档身份和原文件哈希 |
| company_id 与 report_year | 公司和报告年度 |
| text_snapshot_id 与 text_sha256 | 解析器、文本版本和坐标基准 |
| page 与 spans | 1 起始 PDF 物理页；该页文本内 0 起始半开字符区间 |
| quote | 与区间逐字对应的引文，保留单位和必要上下文 |
| table_context | 表格标识、表头、单位、行列和续表关系 |
| dimension 与 source_role | 四维归属及公司自述、审计意见、第三方评价或法规角色 |
| review_status 与 label_source | 候选、人工确认或分歧状态及实际来源 |

证据范围以支持明确答案要点为准，不以整页或整份文档代替实际证据。OCR 与页面不一致时，保留文本快照与原页观察，记录差异后修复快照和重标坐标；不得无记录覆盖旧偏移与哈希。

## 3 问题与参考答案

每题至少保存 query_id、原问题、主维度及关联维度、问题族、事件组、答案类型、公开公司年度条件、answerability、参考答案、答案要点、所需来源角色和 gold 证据组。

可回答性取 answerable、partially_answerable、insufficient 或 conflicting，理由对应冻结输入。需要的外部事实不在输入库时，不能将只供核验的外部资料视为系统可见证据，不能要求模型回答隐藏事实。

答案拆成可核查要点。名单题保存规范化集合，日期题保存格式，数值题保存值、单位、口径与容差。参考答案可有同义表达，但不能查看生成输出后扩大容差或新增有利答案。

每题的必需 evidence_group 对应一个必需答案要点。每个组可以有多个替代 support_option；满足任意一个 option 即命中该组，各 option 内多个必要 evidence_id 或 span 按 AND 处理。保存 group_id、support_option_id 和 required 证据列表。跨页表格的数值和表头可以属于同一 option 的多个必要证据。证据组覆盖率的分母为该题必需组数，全题完整证据成功要求所有必需组命中；不能把命中任意片段当成全题证据充分。

## 4 gold chunk 映射

每个切片方案保存 chunk_scheme_id、chunk_id、原文区间和哈希，并建立 query_id—answer_unit_id—group_id—support_option_id—evidence_id—chunk_id 映射。chunk_id 是方案内标识，gold 主身份为原文证据。

先通过区间生成映射候选，再确认必要语义、单位与上下文是否保留。完整包含核心必要 span 才算支持；同页、任意字符重叠或相似标题均不算。跨多个块的必要证据允许按检出块并集检查完整性，相同证据去重。映射和跨块合并规则在开发阶段明确并在测试前冻结。

跨切片主评价使用相同 token 预算下的证据组完整覆盖；块级 Top-K 作为辅助。父子方案复用相同子块时共用映射，父级扩展另记录最终上下文包含的证据；token 截断后丢失证据不能计作已提供给生成器。

## 5 候选池和相关性

合并 BM25、向量、混合检索和不同切片候选，按原文证据去重，补充人工原文查找和负例。记录候选来源，但标注时尽量隐藏模型、排名、分数和预标答案。保存池深、补搜范围及未判数量，候选池不代表穷尽全库证据。

| 等级 | 判定 |
| --- | --- |
| 2 直接支持 | 回答核心要点，主体、年度、口径及必要上下文正确 |
| 1 辅助支持 | 提供定义或背景，不能独立回答核心要点 |
| 0 不支持 | 无关、主体年度错误、字段口径错误或不支持要点 |
| U 无法判定 | 原文缺失、解析不清或实质分歧尚未解决 |

主召回以等级 2 证据为准，等级 1 单列。U 与未标注的 unjudged 不当作负例。稀疏池化标签下，报告对已判证据的 Hit、MRR、Recall 和证据组覆盖并说明限制；评价截断范围未充分判定时不报告看似完整的 Precision 或 nDCG。报告分级 nDCG 前固定 gain、截断、去重与 IDCG 规则，说明跨切片的单元差异。

## 6 人工确认和过程记录

正式 gold 均须真实人工确认。建议测试题和难例由另一人员独立复核，保留原判后仲裁；只有一人时明确单人标注及可靠性限制，不能宣称双人盲审或计算虚构的人际一致性。

保存 annotator_id、实际角色、时间、原判、理由、复核人和最终决定。人员背景、复核覆盖与一致性按实际记录描述。AI 定位、AI 预标、人工确认和人工仲裁使用不同 label_source。一致性只在真实独立重标子集上按实际人数、单位和等级统计，不能把 AI 两通道一致性写成人工一致性。

现有 weak_auto、ai_dual_pass_adjudicated 与历史回答评分保留原来源。文件名含 gold、已有引用或助手认为正确，都不代表本次 gold 确认。历史标签须逐项核对原文、任务适配与暴露状态并留下人工确认记录，才可进入相应的新版本。

## 7 开发测试隔离

按语义问题族、同一事件和重叠必要证据建立连通组，再分开发与测试。共享法规文档本身不连接所有问题，但重叠目标证据须审查；同公司不同题不自动视为独立。保存组划分、暴露登记、种子和理由。

开发标注用于完善候选和选择配置；测试 gold 在配置固定后封存，不供运行时检索、提示构造或人工补答案。历史暴露不能通过重命名 split 消除。题量、维度分布、可回答性与有效组数以审查为准；问题改写、同事实多次提问与重复生成不当作新增独立样本。

## 8 抽取与问答附加标注

抽取评价单独设置人工审查样本，标出应抽取事实、字段值、单位、维度与证据。只有明确穷尽标注范围，才能计算该范围的抽取 Recall；检索 gold chunk 不能证明整份年报已被穷尽抽取。

问答将内容正确、引用定位和引用语义支持分开。记录实质答案要点、来源、支持或矛盾状态，以及证据不足时是否恰当保留。引用 ID 校验只作结构诊断，不能自动填为事实正确或语义支持。

## 9 冻结与交付

冻结包包含语料与文本快照、问题、参考答案和要点、证据单元、证据组、切片映射、相关性判定、人员记录、划分与暴露登记、版本号和哈希。检查页码区间可还原、ID 无悬空引用和同组不跨开发测试，并人工核对语义与表格上下文。

结构校验通过只证明格式关联满足规则，不能证明语义正确、人员身份或盲态。本规范新增结构须在正式实验前与实现逐项核对，未接入的字段不能写成已有能力。
