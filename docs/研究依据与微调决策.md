# 研究依据与微调决策

核查日期：2026-10-13。本文记录已核查的一手资料与项目判断，属于初步研究依据；完整相关工作检索和复现比较仍在 T01 中继续完成。

## 1. 双 0.6B 配置与微调决策

用户主机只允许 Embedding 和 Reranker 都使用 0.6B，本项目据此固定 Qwen3-Embedding-0.6B 与 Qwen3-Reranker-0.6B。主实验及默认脚本不依赖 4B/8B；生成与 judge 独立使用可用 API 路径，不将检索模型规模误写为生成模型规模。

研究设计判断：双 0.6B 可作为本文的方法研究骨干，不因此降低投稿目标。要证明的是固定骨干时证据核验机制相对强基线的效果，并报告成本和边界；模型规模本身不证明新颖性或保证录用。官方模型卡表明两种 0.6B 模型分别支持相应的检索任务，不代表它们已在本项目语料上达标。

主实验保持模型与上下文/调用预算受控，评价质量及内存、延迟、吞吐的权衡。BGE-M3 等可行检索基线依次加载；如之后取得外部更大模型比较结果，列为独立扩展且记录资源来源，不是当前必须完成的主机任务。

本项目将领域微调设为可选实验，先冻结 Qwen3 Embedding/Reranker 权重完成可靠基线。是否微调由研究假设和开发集表现决定；不能从“目标中科院二区”推导出“必须微调”，也不能将常规微调本身视为充分创新。

[Qwen3 官方说明](https://qwenlm.github.io/blog/qwen3-embedding/)和[技术报告](https://arxiv.org/abs/2506.05176)介绍的是已经训练完成的 Embedding/Reranker 模型，支持任务指令。官方已有训练不等于本项目做过领域训练。正确推理和受控评测是优先工作。

本项目的执行决策如下，属于研究设计判断，而非期刊规定：

| 开发集观察 | 优先处理 | 是否进入微调 |
| --- | --- | --- |
| 接口、指令、块 ID、时间过滤或候选深度有错误 | 修复实现并重跑冻结模型 | 暂不进入 |
| 正确条款经常不在候选池 | 分析切分、路由和召回，再评估 Embedding 适配 | 有可靠训练数据时再决定 |
| 正确条款已召回但排序不佳 | 校正评分、清洗难负例，评估 Reranker 适配 | 优先考虑 Reranker 的 LoRA/参数高效训练 |
| 检索可靠但评价论断不被证据支持 | 改进联合核验、补检索和证据不足处理 | 检索微调不能直接解决 |
| 冻结模型达到主方法所需的检索质量 | 将资源投入方法比较、核验和外部验证 | 可以跳过，并记录理由 |

微调首先核验训练内存与工具支持，不能从 0.6B 推理可运行推断训练可运行。当前不以本机同时训练两个模型为前提；资源不可行时保留冻结权重主线并记录跳过理由。如微调，先按法规族、同源条款与近重复查询分组，再合成训练数据和挖负例。知识库可作为共同检索语料，但测试查询及其标签不能参与训练、模板设计、阈值选择或难负例监督。明确领域内与跨法规泛化两种评测口径。至少提供冻结模型、领域适配模型、训练量/成本和失败案例对比；超参数只在开发集选择。

现有 600 条模板查询和 3,600 条查询—条款对是探索数据，不是已验证的微调成果。query_id 虽不跨 split，同源正例条款仍跨划分；假负例、模板偏差和泄漏审计完成前，不用于最终效果宣称。

## 2. 官方推理接口核验

- [Qwen3-Embedding-0.6B 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)：核对 query 指令、编码方式、归一化和截断；比较指令开关，不将未使用指令的结果混称为同一配置。
- [Qwen3-Reranker-0.6B 模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)：官方 Transformers 示例采用因果语言模型，对 yes/no token 评分；受支持的新版本 CrossEncoder 也是可选路径。当前仓库的 `AutoModelForSequenceClassification` 单头逻辑须校正，并记录依赖与模型 revision。

远端服务也须核验实际加载模型、模板、参数和分数语义，不能仅凭接口名认定与本地等价。量化、显存和速度属于实测配置，现有代码没有 Q4 自动加载能力。主机实测时记录权重精度、batch、截断、设备和峰值内存，不能把理论权重大小等同于运行峰值。

## 4. 拟研究的差异与验证方式

研究焦点是上市公司评价中两个不同支持关系：公司事实是否支持评价论断，以及在该事件时点适用的法规是否支持规范性判断。拟联合核验两种关系，区分事实缺失、法规错误、时间不适用、证据冲突和证据不足，再执行有上限的定向补检索或保留未判定状态。

这种设计仍需和已有 claim-level attribution、证据整理、时间适用性与拒答研究逐项比较，不能预先认定原创。验收需要：问题形式化、明确算法步骤、相同检索/生成骨干上的受控对照、删除组件的消融、人工核验，以及冻结最终测试集上的结果。仅更换 Qwen3 或展示少数成功案例不足以支持该主张。

## 5. 自建数据与公开数据的投稿策略

本项目判断是自建监管评价主集配合公开基准验证，更能同时解释任务价值、标注可信度与方法迁移。公开集省去部分构建工作并便于比较，但需要任务匹配；自建集可以形成数据贡献，也增加抽样、人工复核、泄漏审计与公开复现的工作。Hugging Face 是托管平台，自建数据以后也可在该平台发布；平台名称不能用来推断录用概率。

[HiREC / LOFin 的 Findings ACL 2025 论文](https://aclanthology.org/2025.findings-acl.855/)构建并发布了金融问答基准，其[官方仓库](https://github.com/JaeyoungChoe/LOFin-bench-HiREC)指向 [Hugging Face 数据集](https://huggingface.co/datasets/HYdsl/Open-domain_Financial_QA)。这说明自建数据与公开数据可以是同一数据在不同阶段的状态，并非互斥选择；该实例不证明本项目一定录用。该公开集是外部检索/证据标签候选，尚未下载或运行，任务适配和数据审计见实验设计。
