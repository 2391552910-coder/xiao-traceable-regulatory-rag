## 当前决策（2026-10-27）

**是的，早期计划对眼前这篇论文过于复杂。**它把“现有双源RAG论文收尾”和“年报表格/续表解析新论文”两件事写成一套连做的实验，又把跨模型、跨年和Agent当作近期待办。现阶段只保留一条主线：完成并收紧已有双源RAG实证稿；表格/续表解析作为独立后续课题，不并入当前论文，也不为它重跑一套投稿实验。

### 由文献落实到本项目：压缩后的执行单

1. **收紧现有双源RAG稿。**保留已有G1/G2/G3比较和386份有效评分，逐项核对原始记录、统计口径、表格、限制与正文结论；把结果表述限定为当前公司/问题/模型设置下的观察，不外推为普遍优势。
2. **只补能改变现有结论可信度的验证。**对留出敏感性分析明确标为事后来源核验；若要主张法规时点正确性，先完成R1/R2的92项分歧仲裁和可追溯复核，否则删去/收窄该主张。双人评分分歧保留并报告，不把均分称为金标准。
3. **冻结当前稿，完成复现交付。**核对引用、作者与数据声明，复查正文和复现材料一致性。当前稿不新增跨模型、跨年、Agent或表格解析实验；它们分别回答新的研究问题，不能作为一串默认加做项。

**暂停规则：**以上三项完成后，当前论文阶段收敛。仅当论文主张改变时，才启动一个对应扩展：跨模型验证模型依赖；跨年验证时间迁移；Agent验证迭代决策价值；表格解析验证单元格/续表识别。一次只启动一项，并先冻结相应数据和对照。无需把本项目扩成ARQA、CFQA或AIR-RAG同等规模，才能完成当前稿。

## 结论

项目的长期工程路线不算多余，但把跨模型、跨年度、Agent、外部基准、法规时点、复杂生成核验、鲁棒性和多个检索器都列为当前论文的必做项，范围过大。当前稿件应只检验一个主要方法主张；其他项目保留为后续扩展或在关键缺口触发时再做。

### 这些论文实际怎么做，以及对本项目的尺度判断

- **KBS 短通信（Siddharth & Luo）**：核心工作是从专利句子中识别/生成显式工程关系，论文报告 375,084 个关系样例；随后把方法用于风机专利知识库，并用三个 GPT-4 Turbo 场景演示显式知识如何支持 RAG。它的短篇幅来自**问题和贡献收得很窄**，不是因为没有数据或把端到端 RAG 效果说得很满。对本项目最有用的是：只主张可量化、可复现的表格与跨页证据保留改进；RAG 回答展示可以做实例，不应顶替检索/解析实测。
- **INS（Alier et al.）**：先定位教育语料中缩写与全称错配导致的检索失败，再比较查询时扩展、入库时增强及组合方案；主结果是 Recall@k、nDCG@k、Success@k，并以查询为单位做配对不确定性分析。可借其“错误现象—针对性干预—对应指标”的实验逻辑，不必照搬其约一万份文档的语料规模。
- **Neurocomputing AIR-RAG（Han et al.）**：把自适应迭代检索作为方法贡献，在 TriviaQA、PopQA、HotpotQA、WikiMultiHop、PubHealth、StrategyQA 六个基准上，与多类 RAG 方法比较。多基准、多轮反馈适用于有成熟生成/评测资源的系统论文；本项目当前标签和生成接口条件不足，不应把它当最低门槛。

**判断：旧计划的研究设计不算不合理，但执行顺序过于并行，且对当前数据规模偏重。**把跨模型、跨年、Agent、多检索器、外部基准一起作为近期工作，确实复杂过头。原“必做四件事”也应分阶段：小规模双人标注和最小基线先验证方法是否有信号；只有信号稳定、样本来源审计通过后，才扩大样本、做配对统计和投稿级分析。不能通过删掉独立标注或把开发集改名来制造简化。

### 年报表格/续表论文历史方案（当前稿不执行）

**阶段 A：最小方法验证（仅在启动独立表格/续表论文时执行）**

1. 将论文问题固定为一个：在等 token 预算下，表格/跨页续表的边界线索分配是否比固定排序更能保留回答问题所需的证据。
2. 只保留两个对照和一个方法：固定顺序、表格/邻接优先、边界线索策略。固定候选池、预算、来源上限和解析结果；不调用生成模型，不加入跨模型、Agent 或多年度迁移。
3. 从候选年报中挑出可审计且此前任务暴露风险可接受的材料，先做一个小批人工双标。每个样例标必要证据片段及表格字段；两人分歧经仲裁后冻结。已有9份 PDF 只是来源候选，当前仍未标注，不能当作实验集。
4. 评分前，将仲裁后的每条引文按 PDF 物理页映射回固定解析器生成的原文字符区间，并绑定原 PDF 哈希与文本帧哈希；引文找不到或匹配不唯一时回到人工核对，不能只用页码覆盖代替片段 Recall。
5. 先只看一个主要指标：必要证据片段 Recall；并报告 Precision/F1、输入 token 和逐例失败原因作为辅助诊断。做一次关闭边界线索的消融即可。若小批结果无稳定正向信号，先修改或停止该方法主张，不扩大实验。

**阶段 B：投稿级验证（阶段 A 有信号后再启动）**

扩大独立公司/问题样本；在同一冻结集上做公司/问题配对的区间估计、分组误差分析，并报告人工标注一致性。样本量根据可获得标注量和预期差异确定，不预设一个看似精确但无依据的固定数字。若论文改为声称端到端答案质量，再额外启用固定生成模型，人工核验事实正确性、引用支持与法规时点；否则不加入生成实验。

**阶段 C：扩展实验（仅由论文主张触发）**

跨模型回答“是否依赖特定生成模型”；跨年度回答“是否能迁移到不同报告年份/法规时点”；Agent 对照回答“迭代决策是否优于一次检索”。一次只加一个问题，并保证第二模型、历史标签或调用预算可复现。它们是独立扩展，不是阶段 A 的隐含必做项。

这套安排借鉴了 KBS 短通信的窄主张和 INS 的故障驱动评测；不把 AIR-RAG 六基准设计压缩成形式上相似、实际没有充分数据支持的实验。

## 年报表格/续表论文候选主线（不属于当前双源RAG主稿）

**待验证主张：** 在相同候选池、来源数上限和 6,000 参考 token 预算下，依据片段末尾的截断线索分配证据，能否比固定表格优先或固定邻接优先策略，更完整地保留表格字段与跨页续表的必要证据？

这与项目已经实现的表格/续表解析和边界线索分配相接。当前 8 题、40 个策略上下文用于开发诊断，不能作为最终独立测试结果；“将金标准来源放进上下文”也只代表供给覆盖，不能代表语义检索 Recall 或回答正确。

## 表格/续表论文候选实验（未启动，不是当前必做）

1. **冻结独立评测材料。** 另选未用于策略设计的公司或问题，先核对原文和证据区间，再冻结标签、问题、语料快照、token 预算、方法参数和失败规则。已有 AI 提取或已经看过输出的标签，须在主分析前经过人工核验；开发用的 8 题留作回归。
2. **比较三个条件。** 固定顺序基线、表格优先/邻接优先基线、当前边界线索策略。三组共用同一候选池、同一总预算、同一来源数量限制；不同时变更检索器、提示词或生成模型。
3. **报告与主张对应的指标。** 主指标为人工核定的必要证据片段在最终上下文中的 Recall；同时报告 Precision、F1 或 nDCG（按冻结的相关性等级计算）、覆盖来源角色、token 数与延迟。若将表格解析本身作为贡献，再单独报告人工标注单元格/字段的 Precision、Recall、F1。页面被覆盖或文本被纳入上下文不能代替语义相关性。
4. **作一项机制消融和误差分析。** 关闭截断线索优先规则，其他条件不变；归类表格字段漏失、跨页续行漏失、预算冲突和误纳噪声。按公司/问题配对报告差值和不确定性；样本/公司数不足时如实给区间，不包装显著性。

若当前论文仍要声称端到端 RAG 答案质量，还需在上述冻结材料上做一次固定上下文生成对照，并由独立人员核验答案事实、引用支持和法规时点。生成服务暂不可用时，先完成可离线验证的检索/证据分配论文结果，不把生成质量写成已测得。

## 执行顺序和当前门槛

1. 先盘点可用于独立评测的公司、问题和人工标签，按公司隔离开发与验证；不足时先补最小的盲审集，不再开发新策略。
2. 冻结评测包后运行三条件证据分配实验，输出逐题材料、指标、配对区间和失败案例。
3. 由两名复核者盲审抽样证据及输出，记录分歧和仲裁；尚未复核的单元保留未知，不自动当正确。
4. 更新英文主稿、图表、复现说明和README。跨模型、跨年或Agent只在达到表中条件后追加。

## 基于最新交付的计划校正

### 当前不是“从零开始的小型表格实验”

复核现有交付后，近期论文主体应继续以**双源RAG受控实证研究**为准，而不是把10月27日新增的表格解析开发集改成主论文。`results/paper/substantial_revision_20261023_01/年报与法规双源RAG_大幅修订研究长稿.docx` 已有20家公司、60题、G1/G2/G3主比较、检索消融、来源缺失和同系列服务版本分析；记录为400个计划回答、386个结构有效且经两位评分者独立评分的输出，并含1800个预算回放。其结果是探索性人工评分，不是无争议金标准：232个评分条目存在分歧、尚未仲裁，正式H1/H2也未确立。故不要再把“跨模型、跨年、Agent都没做”作为当前事实，也不要把现有扩展说成严格的独立跨厂商泛化。

该稿目前可支持的核心叙述应保持有限：在现有样本及量表下，按来源分路的G2相对合并检索G1出现正向配对评分差异；G3只在完全相同证据上增加来源角色提示，未显示稳定增量。来源同现率、位置命中、结构有效率、人工评分和法规时点正确性是不同结果，不能互相替代。详细数值及适用限制以长稿、原始评分和可复算脚本为准，不在计划文件中另造一套结果。

### 参考发表论文后，近期计划收敛为三项

1. **定稿主张和结果边界。**沿用长稿已有的G1/G2/G3核心对照；突出来源角色分路在本任务里的观察，不宣称普遍RAG改进、普遍正确性或法规时点已验证。保留零增益、反向结果和失败单元。
2. **完成最必要的验证修订。**逐项核对10月26日留出分析中的参考标签勘误、原文证据与40个最终单元；将看过输出后才改的标签明确标为事后勘误分析。主稿已保留两位评分者原分并报告分歧与评分者敏感性；只有在确有仲裁记录后才称“仲裁金标准”。不要为凑一个新主实验而重跑已保存的回答。
3. **交付可复算稿。**校准中文与英文稿的结果、限制、表图、附录和运行状态，保留原始记录及失败原因；最后核对参考文献、作者声明、目标期刊格式和可复算材料。

KBS的短通信展示了“一个明确抽取任务 + 大规模任务数据 + 领域知识库示例”；INS论文展示了“一个检索故障 + 少数定向干预 + 检索指标与配对不确定性”；AIR-RAG则依赖17,811条偏好样本、六个基准和多组消融来支撑适配器及迭代检索贡献。对本项目可借鉴的是**主张与证据匹配、负结果透明、对照变量隔离**，不是把三个领域的问题、指标和实验量叠加到一篇稿件里。KBS短通信也不代表工作量小；AIR-RAG也不是二区论文的统一清单。

### 参考年报 QA 论文后的计划收敛

1. **当前主稿仍以双源 RAG 受控实证为主线。** 沿用已有 G1/G2/G3 和两位评分者对386个有效输出的评分；把来源分路结果作为当前样本下的观察，不扩写成普遍 RAG 优势或法规时点有效性结论。保留评分分歧，不把均分改称金标准。
2. **不为模仿文献规模而重做数据集。** ARQA/CFQA说明了人工核验、问题类型与证据绑定的重要性，但其约2,500/500题规模不是当前投稿前的硬门槛。主稿先把既有数据、统计口径、失败单元与限制完整写清。
3. **只处理会改变论文结论的验证事项。** 继续核对留出分析的事后标签勘误和原文依据；若留出结果保留，明确称敏感性/探索分析。法规版次复核已收到R1/R2，但92项字段差异尚待仲裁且身份未认证，不能把复核标签写入正式索引或当金标准。若当前主张不依赖时点正确性，不把该支线硬塞进主实验。
4. **表格续表、Agent、跨年和跨模型分开管理。** 表格解析是独立方法支线；跨年/Agent已有小样本探索结果，跨服务版本不是跨模型族验证。除非主论文新增相应主张，否则不再扩建这些实验。
5. **完成论文交付闭环。** 对照原始运行记录核对正文、表格、附录、限制和中英文稿；确认已发表/投稿引用准确、作者声明据实、公开复算材料不含密钥及未授权原件。期刊分区和录用不能由篇幅或图表数量保证。

**结论：** 当前计划的主要问题是把长期方向混进近期待办，而非研究验证本身过多。近期应聚焦“核验已有证据—收紧主张—完成一份可复算主稿”；不新增跨模型、Agent、表格或跨年实验来凑复杂度。
