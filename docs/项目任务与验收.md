# 项目任务与验收

任务对齐日期：2026-10-13。本文是项目目标、范围与优先级的统一入口；实际进度以可核验的数据、代码和实验记录为准。

## 1. 已确认的总任务

完成《面向上市公司主体自律评价的可追溯检索增强生成方法》小论文的算法与实验，以中科院二区计算机类期刊为投稿目标。小论文的方法、数据规范和实验结论将作为大论文的一个支撑。

最终交付包括可投稿的论文稿件、方法实现、可复现的数据与实验产物，以及供大论文复用的方法说明和接口。期刊分区须在选刊与投稿时核验年份、大类和小类口径，不能用 JCR Q2 替代中科院二区。录用结果由期刊评审决定。

## 2. 方法边界

评价对象是 A 股上市公司的主体自律表现，覆盖 D1 信息披露质量、D2 董事会治理有效性、D3 内部控制与合规性、D4 第三方声誉。

系统输入为用户上传/导入的年报 PDF 和法规文件。系统分别解析、切分、保留来源与版本/适用时间坐标并建立索引；对评价问题分别检索年报中的公司证据和适用法规，再生成带逐项来源引用的内容，并在证据不足时说明不能支持的部分。年报结构化事实候选仅是可选的定位/评测辅助，不是系统检索或生成的必要前置数据。0–100 维度得分只作为辅助输出；在评分规则和人工参照尚未建立前，不宣称得分具有客观测量效度。

已有法规语料的条款切分、混合检索、维度路由和引用约束组成研究原型。目标方法面向年报库与法规库双路检索，并核验每条评价论断是否分别得到年报证据和适用法规支持；必要时执行有上限的补检索并报告证据不足。目标流程尚未完整实现，其新颖性和收益须通过相关工作比较与独立测试集验证。

引用约束、条款切分、混合检索、重排和拒答各自已有相关工作；不能将组件组合、采用 Qwen3 或常规 LoRA 微调直接写成原创算法贡献。研究依据见[研究依据与微调决策](研究依据与微调决策.md)。

## 3. 模型与微调决策

- Qwen3 在本项目承担 Embedding 和 Reranker，属于检索模块；生成评价的 LLM 单独记录。
- 主机限制已确认：本地 Embedding 和 Reranker 均固定使用 0.6B，即 Qwen3-Embedding-0.6B 和 Qwen3-Reranker-0.6B。第一阶段冻结权重，与 BM25、BGE-M3 等硬件可行基线受控比较；不同模型按需依次加载，主实验不要求 4B/8B 检索模型。模型大小、设备与成本须记录，不能把配置名当成真实运行证据。
- 双 0.6B 不改变二区投稿目标。论文应验证相同小规模检索骨干下，联合核验方法的质量收益、适用边界及内存/延迟/调用成本；不宣称仅凭小模型取得录用，也不宣称未测试的模型规模泛化。生成与 judge 单独配置，可使用现有 API 路径，不在主机强制加载大模型。
- 微调为条件性扩展：先排除接口、查询指令、切分、路由和候选池错误，再根据开发集错误诊断决定。候选池已有正确条款而排序差时，优先评估 Reranker 的领域适配；召回不足时再评估 Embedding。
- 微调须先确认主机可承担训练；0.6B 推理可运行不等于训练内存足够，不假设可以同时训练两个模型。微调必须有去重后的训练/开发/测试划分、可靠正负例、冻结模型对照与训练成本记录。现有模板合成样本用于联调和探索，不直接作为最终论文测试集。

## 4. 数据与实验规模

数据策略为“年报 PDF 文档库＋有版本与时间信息的法规文档库＋问题级双源证据评测集”。运行时直接检索文档段落，无须预先把全部年报整理成结构化事实库。人工标注用于核验问题对应的年报支持段落、适用法规条款、生成论断与引用关系；公开基准仅用于标签和任务相匹配的外部验证。

下列规模是本项目的规划目标，不是期刊统一规定；先用开发集估计方差与成本，再冻结正式方案。任何调整须在查看最终测试结果之前记录原因。

| 数据 | 当前状态 | 下一阶段目标 |
| --- | --- | --- |
| 监管知识库 | 清单 315 篇；目录加载 319 篇 | 审计全文、重复、版本和适用日期；DOC004 全文正式登记，演示节选隔离；冻结索引及哈希 |
| 检索查询 | 弱标签 40 条；AI 双通道 gold 候选 40 条 | 扩至至少 200 条，四维度各至少 50 条；40 条开发、160 条最终测试，按语义问题族隔离并人工复核 |

39 家年报是当前可用的先导文档集合，不代表 A 股总体样本，也不足以支持总体违规率推断。报告年度、公告日期和事件日期须分开；如回答涉及具体事件且年报无法确定事件时间，须结合适用法规和可用来源标注不确定性。

系统回答只陈述被检索证据支持的内容。年报未提及不能推断事项不存在；若问题需要年报之外的 ESG、舆情或处罚原始事实，而当前双库没有相应来源，应明确说明证据缺口，不补造信息。2025 年报或跨年度测试另行冻结，不能与 2024 年主实验混用。

当前 T01 完成初步文献核查；双源目标流程与评测仍待实现和验收。39 份 PDF 的身份核验只证明文档可作为年报输入，不代表上传界面、完整双库流程或正式生成评测已经完成。

### 正式实验前已发现的阻塞项

1. `02/04` 默认读取 `weak_auto` 查询，而现有 gold 也是 AI 标注，尚非人工最终测试集。
2. 本地 Qwen3 Reranker 采用序列分类头加载；须校正为官方受支持的输入和评分路径，避免随机分类头或错误分数。
3. Embedding 查询指令、依赖兼容性、截断长度与远端参数须统一；配置注释中的量化并没有实际加载实现。
4. 路由目前先截取全库候选再过滤，并非在维度子库中完整召回；路由消融还须分离查询扩展和子库过滤。
5. 滑窗使用 `W` 块 ID，条款标注使用 `C` 块 ID，当前消融不能直接以 ID 相等比较。
6. `05` 会覆盖同一公司/维度/模式的重复生成记录；须先聚合重复，再按公司处理相关性。
7. 当前自动引用匹配只验证名称和条款，不能证明语义支持；无引用、真实但未召回、虚构引用须分开统计。
8. 当前 judge 实际复用生成客户端，独立 judge 配置未接线；`06` 只实现检索图，其他图仍待完成。
9. 合成集虽然 query_id 不跨划分，同源正例条款和法规仍跨 train/dev/test；微调前须按法规族分组重建。

## 6. 最终验收口径

正式结论必须来自真实模型、冻结数据和可复现明细，包含强基线、组件消融、跨模型验证、人工核验及成本。若结果不支持假设，报告失败原因并修正方法，不能预设提升、指定必须出现的 p 值或删除负结果。

论文与大论文共用同一版本的方法定义、数据口径、证据接口和结论。与大论文系统的对接以实际抽取模块和结构化事实接口为准，不预设未核验的章节号或已有系统能力。
